## Wrapper, scheduling, and finalizer changes

The audit wrapper equals worker120 after request/tag substitution. It inventories source-matching successful builds with existing objects, generates Audit text, checks successful compilation, printed-line count and permitted axiom sets, then performs replay and stores booleans. It does not compare exact theorem names or uniqueness itself, does not stop replay on a false audit boolean, and does not raise merely because an audit/replay boolean is false. Compiler scheduling changes from worker120's serial batch to bounded foreground pools. The batch helper defaults to three workers and 150-second compiler limits; the DAG scheduler uses up to six workers, source imports among its planned modules, and an absolute 02:48 UTC scheduling cutoff. Its `accepted` terminology means source-matching successful builds, not replay acceptance. It can report outer success after interrupted compiler receipts. These labels are separated from validation status here.

The replay-chunk wrapper uses two worker threads and chunks of at most twenty modules with 120-second limits. It filters for individually audited but false replay flags, submits chunk jobs, and updates flags after successful returns. Compiled imports outside a chunk remain reused. It does not establish that every dependency body was selected in a successful chunk. Its interrupted outer command and recorded chunk receipts support no additional successful target.

The rewritten finalizer explicitly supports partial validation. It restores prior successful replay flags only when receipt, validation-entry, and current-source hashes match; checks validation-entry source/object hashes and prior preservation; calculates accepted modules as the intersection of true axiom/replay flags; and separately reports compiled pending and unbuilt sources. It does not require all compiled modules to be accepted or all candidates to be built. Its failure list concerns the checks it performs, not an assertion of complete replay coverage. The compiler inventory checks successful receipts and present objects but cannot establish invocation-time object identity by itself.

Source discovery now uses `*MAE2*.lean`, and research manifest inclusion matches any Lean filename containing `MAE2`, fixing worker120's helper-suffix omission for this observed archive.
