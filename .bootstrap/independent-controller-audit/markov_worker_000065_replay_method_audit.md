## The actual checking operation

- `/Users/sasha/.elan/toolchains/leanprover--lean4---v4.32.2/src/lean/LeanChecker.lean`.

After removing comments and normalizing whitespace, the bodies of `replayKnown6d` and `LeanChecker.replayFromImports` are identical. The only dispatch changes are explicit module arguments and sequential execution, replacing the official command's recursive prefix-based discovery and task dispatch. The alternate command has no `--fresh` mode.

For each target, both methods:

1. Resolve the target `.olean` by the Lean search path; fail if it is absent.
2. Load the exported object and available server/private parts, using the last, most private part's constant table. For these nine modules only the ordinary `.olean` is present; none of the reviewed files uses the new `module` declaration or has a missing currently present private/server sibling.
3. Construct the target's starting environment from the imports recorded in its object, through `importModulesCore` and `finalizeImport ... {} 0 false false (isModule := true)`.
4. Pass the complete collected constant map to `Environment.replay`.
5. Replay ordinary theorem declarations as `Declaration.thmDecl`, including their stored proof expressions, through **`Kernel.Environment.addDeclCore 0`**, the checked `lean_add_decl` entry point. This is not `addDeclWithoutChecking`, nor the elaborator wrapper which consults `debug.skipKernelTC`.
6. Propagate an exception on a rejected declaration; the "replay passed" line is printed only after successful return.

Thus the alternate method does not substitute statement parsing, tactic success, or axiom-printing for proof checking. Its use of `unsafe` for the operational IO driver does not turn the mathematical theorem declarations into unsafe declarations.

There are standard qualifications shared with the pinned checker:

- `Environment.replay` skips **unsafe and partial constants**. `ConstantInfo.isUnsafe` is always false for theorem declarations and `isPartial` applies only to definitions. No unsafe or partial declarations occur in these nine mathematical sources.
- Constructors and recursors are checked for equality with those regenerated by the kernel from replayed inductives, rather than added independently.
- A duplicate imported theorem with the same name, type, universe parameters and mutual-block list is skipped; its alternative stored proof body is not compared. This is exactly the official implementation, not a change introduced by the worker. No duplicate source declaration or exceptional mechanism is indicated in the reviewed ordinary modules and matching successful builds.
- Axioms are accepted **as axioms**. Replay alone does not reject `sorryAx`, native-decision axioms, or arbitrary extra axioms. The no-extra-axiom conclusion below additionally uses the reviewed mathematical sources and successful-build axiom records.
- The default starting environment loads imported declarations rather than recursively replaying their proofs. An explicit list of nine targets is not all imports, all project modules, or the official `--fresh` operation.
