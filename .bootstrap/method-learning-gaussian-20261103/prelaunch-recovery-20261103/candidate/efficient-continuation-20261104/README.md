# Inactive efficient continuation

This is an operational candidate for the existing autonomous Gaussian goal.
No live source, authorization, study, proof, model, or budget is changed by
creating it or passing its synthetic tests. ROOT must independently qualify the
source and concrete handoff before launching a fresh owned coordinator.
`FullPositivity` remains open; no mathematical suggestion is sent to the proposer.

The former coordinator (`867691...`) recursively repeated equivalent historical
native checks: 25 full dependency identities per input check, twice per child
command. `admission.py` first calls its complete pure history/source/receipt
verifier with `initial=False,native_checks=False`. It then runs each distinct
native-only obligation exactly once, through unchanged existing APIs:

1. The original source-revision `verify_revision(..., initial=False,
   native_checks=True)`: implementation/evidence/authorization and q4 deployment.
2. The prepared successful deployment's `reuse_deployment`.
3. The closed-round helper's `verify_finished(..., require_current_state=False,
   native_checks=True)`: genuine native study verification and snapshot binding.

These are three dependency identities in a successful command admission, rather
than fifty. Existing owner, native CLI, Arm-session and proof checks still run;
three is not the total number of checks in the entire research session. There is
no persistent cache, mtime substitute, fake hash or monkeypatch in production.
All source/history branches remain checked. Synthetic call counts establish
this code-path reduction; live speed, learning gains and disk-loss causality
have not been measured or established.

The unchanged cheap native headroom guard runs before expensive admission and
again immediately before returning to the owned-child launcher. Only the two
recognized admission disk/memory exceptions may wait, with 15-second sleeps and
STOP checks. A second STOP check after successful expensive qualification
prevents launching a new child if STOP arrived during hashing. Cleanup holds,
observer failures and other errors fail closed.
The original funded command performs the new dynamic input check once before
its actual INTENT/Popen. Metadata written earlier is explicitly labeled
`binding_only_pre_admission`. Inherited curator arguments continue to identify
the executing prepared component (`cd2547...`); coordinator, admission, runtime
and predecessor identities are separately recorded in config, CURRENT,
checkpoint, CONTINUATION_ADOPTION and per-command source bindings.

The outer configuration has exactly `schema`, `owner_source`,
`admission_source`, `runtime_source`, `predecessor_source`,
`predecessor_config`, and `handoff`. Each reference contains `path` and `sha256`.
Its schema is `math-gkm.gaussian-efficient-owner.v1`. The predecessor source and
configuration are the frozen `867691...` and `6533a0...` artifacts.

The protected handoff schema is `math-gkm.gaussian-efficient-handoff.v1`. It
contains `study`, `epoch`, `arm: exploration`, predecessor source/config/output,
checkpoint reference, `exit` reference, full contract/native/profile SHA values,
current seal/protocol references, and `states`. Each of the two state entries
contains `current` and `archive` references with identical byte hashes. The
archives are opaque private records; they never enter a public source package.
The exit reference authenticates a ROOT-authored
`math-gkm.owned-controller-exit.v1` record containing `source`, `config`,
`output`, `actual_numeric_exit_observed: true`, numeric non-success returncode,
`owned_tool_handle`, `completion_reference`, and `observed_at`. It records an
actual observed closed handle, never an inferred PID or file-based liveness.

Initial admission checks the exact current opaque state pins and approved
settled-role metadata. Closed receipts awaiting native bookkeeping can remain;
no receipt, counter, workspace or prior paid action is reset. Later checks keep
the immutable handoff but allow genuine state evolution. The handoff also lists every predecessor command as exact intent/exit/log
references. All observed command directories must be listed, each EXIT must
record an actual numeric owned closure and authenticate its log bytes, and no
open or extra command directory is accepted. Initial admission refuses any
retained study STOP; this code never silently clears one. The current epoch and
round are not hardcoded to the former round-9 boundary. The unchanged inherited
`continue_until_boundary` loop resumes exploration, then normal fresh curation
and original `ccce` migration continue through funded epochs until exact full
proof plus independent English acceptance, an explicit stop, or operational
uncertainty. Native `6f3c44...`, contract `a9802e...`, profile `99be85...`,
1800-second bounds, all memory/disk floors and prior uncertainty bridges remain
unchanged. The earlier comparison has revised source history; no causal winner
or whole-continuation Gödel-machine certification is claimed.

`runtime.py` is a separately pinned adapter owned by the reconciliation author.
The coordinator invokes it with `--operation run|recover --study ABS --arm
exploration --source-sha256 SELF_SHA`. It retains native scheduling and gates;
its narrowly scoped cached-order handling is documented independently.
`--status-path` binds one public `commands/NNNNNN/RUNTIME_STATUS.json` file.
The read-only status response reports that source-bound runtime phase separately
from the coordinator phase, so a runtime headroom wait is visible without
claiming process liveness.

Prospective launch, ROOT only, after actual previous-owner closure and review:

```
/opt/homebrew/bin/python3 coordinator.py --config ABS_NEW_CONFIG --output ABS_FRESH_OUTPUT
```

`status_public.py` requires a separately approved registration binding its source,
coordinator, config and output. It uses pure verification and selected public
metadata only; it neither runs proof checks nor asserts process liveness.
`test_efficient.py` uses neutral fixtures and mocked gate results, never private
research/evaluation data or real dependency hashing, models or compilers.
