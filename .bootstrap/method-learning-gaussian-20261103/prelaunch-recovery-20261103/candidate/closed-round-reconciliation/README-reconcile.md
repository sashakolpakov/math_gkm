# Exact cached-round reconciliation candidate

This external adapter closes one already paid, failed researcher round through the unchanged native `Arm.research_round`. It has its own source SHA. Native sources, the original plan/request/receipts, research allowances, and accepted mathematics remain unchanged. A `FINISHED.json` here certifies operational bookkeeping only; it never certifies the mathematical target.

The recorded obstruction is a permutation of an in-memory portfolio map after canonical JSON persistence. The portfolio list and the program's input hash consequently differed when the same request was rendered again. The adapter tries only the original request order and its inverse (to account for `reverse_portfolio`). It proceeds only when the canonical staged research digest is unchanged **and the full regenerated request, including program execution input hash, equals the immutable original request**. It never rewrites the plan or request.

`finish_closed_round(study, mode="exploration", round_index=..., expected_state_sha256=..., diagnosis={"path": ..., "sha256": ...}, expected_source_sha256=..., output=...)` requires a fresh output directory below this repository's `.bootstrap`, exact native/source bindings, an authenticated typed diagnostic wrapper, and an exact current-state comparison under the native controller lock. The current research must equal the original round-start state; no round history, snapshot, or staging snapshot may exist. The protocol must be clear, both old jobs accounted exactly once, and the actual resource failure must have no cleanup hold or incomplete-cleanup indication. The diagnostic does not invent a cleanup-completion flag.

Before any round effect the adapter saves an opaque, read-only `BEFORE_STATE.raw` and an exclusive `INTENT.json`. Its subclass permits only the two original cached job identities. Every call must have an already authenticated numeric receipt and the full original request. The native `Arm.call` then takes its existing-receipt branch; no new worker is admitted. The unchanged failed-result branch records feedback and the failure observation, snapshots the retained sources through the ordinary native code, advances one round, and saves the state. It admits no failed payload as mathematics.

The adapter verifies that all hosted call/meta counts, reservation seconds, pools, receipt registries and hashes, protocol accounting, failure count, knowledge/components, and source inventory are unchanged. It preserves the original input files byte for byte, authenticates the native snapshot and history, and saves `AFTER_STATE.raw` plus `FINISHED.json`. A failure retains `INTENT.json` and class-only `FAILED.json`; there is no automatic rollback or replay. A second invocation cannot reuse the output directory.

`verify_finished(study, output, expected_source_sha256=..., require_current_state=True, native_checks=True)` returns fixed public receipt/source/round metadata with `root_proved: false`. It binds both opaque state archives to the same original before-state and recorded after-state, authenticates the original diagnostic and input files, and checks unchanged accounting and admissions using the pinned E1 lexical projection. Only `round` and `phase` are decoded from those archives. `require_current_state=True` is the initial handoff comparison. Later continuation and status calls use `False`, because legitimate research changes the current state. Immutable source, archives, old inputs, snapshot, and history bindings remain mandatory.

`native_checks=False` additionally keeps the status reader to source hashes, bounded public metadata, and E1 projections. It does not invoke the native study verifier, models, compilers, or write APIs. Normal execution uses the unchanged native verifier and snapshot verifier. The coordinator and its public reader are separate sources documented in `README-coordinator.md`.

Neutral tests forbid `subprocess.Popen` and `subprocess.run`. They exercise the actual unchanged native failed-round body with a cached native receipt, exact order restoration (including reversal), fresh-call refusal, request/receipt tampering, the once-only output and current-state comparison, immutable archive relations, cleanup/marker guards, and privacy of the E1 reader. Mocked functions are confined to synthetic temporary fixtures; production never monkeypatches native code or source identities. Root alone may execute this candidate on actual private artifacts after independent review.
