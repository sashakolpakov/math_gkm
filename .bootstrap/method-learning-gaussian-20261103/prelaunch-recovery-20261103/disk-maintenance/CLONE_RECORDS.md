This is an inactive APFS exact-duplicate sharing candidate. It never recompresses records or decodes their mathematical/model payloads. It uses only the 4049 original paths enumerated in a protected `math-gkm.qualified-compressed-records.v1` index, with their successful compression journals, closed-batch receipts and original replacement metadata. A root-reviewed `math-gkm.compressed-clone-groups.v1` file selects equal hash/byte-count groups and the canonical path with smallest allocated representation, then lexical path. Every participating record must remain compressed (flags 32), single-link and within the unchanged 256 KiB–64 MiB logical bound. Current Gaussian/native records and other unindexed paths cannot participate.

Before effects, the source/index/groups/attestation hashes require a separate protected `math-gkm.compressed-clone-review.v1` record with `approved: true`. Original successful journals, closed batch receipts, frozen archival contexts, current identity/metadata and streaming SHA256/read counts are rechecked. Existing reviewed archival and V2 source files are imported by exact hash and remain unchanged. Their global heavy and old controller fences remain in use; native model/Lean guards are unchanged.

A genuine `clonefile` syscall creates an absent same-directory temporary destination. Its inode must be distinct from both canonical and original target, with nlink 1, before any metadata restoration. The target's own uid/gid/mode/mtime are applied to that new inode, then bytes, compression flag, identity and metadata are verified and fsynced. The original target remains as a fresh owned hard-link backup through atomic replacement, post-verification and another fsync. Only the verified own backup is then removed. Canonical and target logical paths remain separate single-link inodes. A failure restores the verified original only while exact owned identities match; unknown foreign changes retain uncertain artifacts for reconciliation. No blind retry or process-liveness claim is provided.

Batch work uses a 55-second start cutoff to leave a completion margin within the 60-second maintenance allowance, the unchanged 2 GiB plus file temporary-space floor, and an integer free-space target 12–32 GiB. Physical free space is measured before and after; reported deltas are observations, not attribution. Per-file st_blocks can remain unchanged for shared APFS extents and is never reported as reclaimed disk. Copy-on-write sharing is meaningful only on the qualified filesystem. The root separately qualifies the actual compressed-file syscall and ordinary readers in an escalated fixture and canary; these tests model cloning and establish no physical sharing claim.

Each successful clone changes the target inode, so replaying an identical group plan will refuse its stale metadata. For a later batch, retain the original full index but create newly pinned/reviewed groups excluding completed targets; untouched canonical paths and remaining indexed targets retain their identities. There is no automatic resume or silent index rewrite.

The CLI takes `--source-sha256`, `--index`, `--index-sha256`, `--groups`, `--groups-sha256`, `--attestation`, `--attestation-sha256`, `--review`, `--review-sha256`, fresh protected `--out`, `--escalated-context-qualified`, and optional `--target-free-gib`. Runtime indices, group manifests, reviews, contexts and journals remain private. No real clone, compression, research action or native machinery change occurred during authoring.
