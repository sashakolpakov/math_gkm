## Main finding

V2 is an executable **experimental research-policy study**, with a meaningful exact-root validation path. It does not carry all of the original construction mission into its active execution path. In particular, checked context attachment/gluing, reflective execution semantics, and persistent executable self-rewrite remain separate unmet or historical obligations. Its explicit refusal to claim a certified Gödel switch is correct. That disclaimer should be accompanied by an explicit requirement/status register so these requirements are not silently replaced by four prompt-policy fields and a finite transfer benchmark.

The original project was already careful about these distinctions. `docs/GKM.md` separates the running research loop, the checked finite continuation model, and Python orchestration. The old `SwitchGate.install(certified=True)` rejects because the host refinement, measured cost and timed-response coupling are unproved. Thus the missing full host bridge is **not a regression from an already certified general Gödel machine**. The original obligation remains outstanding; v2 has not discharged it.

## What the ARC lineage contributes, and what must not be imported

The scoped ARC reading used `arc/ARC.md`, its root README, the repository-ground-truth matrix, and architectural sections of `manuscript/arc_agi3.tex`; it did not inspect unrelated agent histories or game solutions. A filename discovery initially encountered history filenames; no history contents were read. The archived `SPEC_logical_cofibrant.md` was read as an explicitly retired design example, not a current interface specification or a source of mathematical strategies.

The ARC manuscript expressly substitutes finite behavioral replay for a formal utility proof. Its syntactic category uses typed graph presentations and designates monomorphisms as cofibrations; source persistence, source pushouts and finite behavior are distinct claims. It explicitly does not assume arbitrary Python edits preserve interfaces or that a global behavior functor preserves every colimit. That is compatible with the narrower math_gkm `GLUING.md`: the old repository has concrete type/function pushout and conditional semantic attachment/transport theorems, but no implemented general model-category structure, Grothendieck opfibration, or arbitrary dependent-Lean attachment compiler.

ARC's external game levels and literal finite action programs are not mathematical research levels. Its fairness/full-support assumptions and finite recognizer cannot be silently transferred to opaque Astra proof search. Its historical source-size allocation heuristics and prospective free-energy curiosity are also **not authorization to use compression in this math harness**: MISSION/DESIGN impose the later, explicit audit-only constraint. Preserve the reusable-component/interface/provenance ideas without copying those incompatible selection rules.

## Required documentation reconciliation

The new harness should have a concise status ledger for the original obligations with one of: active and tested; implemented but awaiting live canary; historical theorem with exact model scope; unavailable/deferred; or explicitly excluded by the new experiment's authorization. In particular:

1. Describe policy-guidance adaptation separately from persistent code self-rewriting and certified switching.
2. Identify which protocol/gluing/continuation theorems are actually executed or relied on by v2; a copied source file is not integration.
3. Call exact interface and transport checks what they establish, without claiming generic cofibered/cofibrant gluing or all-capability retention.
4. Preserve the full action space as an obligation, including a safely reviewed code-change proposal path if full original scope is claimed; absent paths must be stated.
5. Keep every empirical improvement, partial proof, model theorem, live validation result and certified-switch claim in its own evidence class.
6. Bind final source and test evidence after the builder stops changing files. At one observed check, the install manifest was already stale against five files; its earlier successful test log therefore cannot certify later bytes.

These are engineering traceability requirements, not a mathematical research plan. They do not require the supervisor to implement a proof, choose a representation, direct the researcher, or falsely turn an experimental branch into a certified machine.
